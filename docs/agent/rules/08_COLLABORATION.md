## 1. Git 규칙

### 브랜치 전략 🧩
- 상태: 🧩 기본값
- 결정: `main`(안정) + 작업 브랜치(예: `vibe_coding`, `feat/<케밥-설명>`). AI는 작업 브랜치에서만 커밋한다. `main` 반영(merge·PR)은 사용자 확인 후
- 결정일:

### 커밋 주기 🧩
- 상태: 🧩 기본값
- 결정: **업무 묶음 단위로 커밋** — 하나의 기능·수정·문서 갱신 묶음이 검증(07)을 통과하면 즉시 커밋한다. 여러 묶음을 한 커밋에 섞지 않고, 검증 실패 상태로 커밋하지 않는다
- 이유: 사용자가 반복 지시 — "특정 업무 묶음마다 commit 진행"
- 결정일:

### 커밋 컨벤션 🧩
- 상태: 🧩 기본값
- 결정: Conventional Commits 접두어(`feat:` `fix:` `docs:` `test:` `refactor:` `chore:`) + 한국어 요약. 본문에 무엇·왜, 관련 specs ID
- 결정일:

### push / pull 🧩
- 상태: 🧩 기본값
- 결정:
  - 작업 시작 전 원격이 있으면 `git pull --rebase`로 최신화
  - 일정 업무 묶음의 검증이 끝나면 작업 브랜치를 push
  - force push·`main` 직접 push·원격 브랜치 삭제는 사용자 확인 후에만
- 결정일:

### 커밋 금지 대상 🧩
- 상태: 🧩 기본값
- 결정: `.env`, 키·토큰이 든 파일, 대용량 데이터·모델 파일, 테스트 리포트, 실데이터(개인정보) 파일
