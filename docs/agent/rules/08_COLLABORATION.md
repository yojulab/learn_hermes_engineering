## 1. Git 규칙

### 브랜치 전략
- 상태: ✅ 결정 (2026-08-05 변경 — 99_DECISIONS 기록. 8/6 강사 GitHub 교육에서 다른 전략 지정 시 재변경)
- 선택지: main 단일 / GitHub Flow / Git Flow
- 결정: **main·dev 2단 + 기능 브랜치** — `feat/*`(작업) → PR → `dev`(통합) → 마일스톤 시점에 dev→main PR. main은 초기 상태에서 시작해 검증된 결과만 수용
- 이유: 5명·4주 규모에 적합 + main을 깨끗한 시연 기준선으로 유지. 강사 규칙 "브랜치 구성 필수" 충족
- 결정일: 2026-08-05

### 커밋 컨벤션
- 상태: ✅ 결정
- 선택지: 자유 형식 / Conventional Commits / 한국어 요약
- 결정: **Conventional Commits** — `feat:` `fix:` `docs:` `test:` 등 접두어 + 한국어 요약 본문
- 결정일: 2026-08-05

### PR / 코드 리뷰 규칙
- 상태: ✅ 결정 (2026-08-05 머지 권한 구체화)
- 결정: 팀원은 `feat/*` → dev로 PR 생성, **리뷰·머지는 CTO 전담** (품질 게이트 일원화). CTO 본인 작업 PR은 팀원 1인 리뷰 권장, 긴급 시 셀프 머지 허용(2026-08-05 인터뷰에서 금지 조항 명시적으로 제외). PR 올리기 전 로컬 전체 테스트 통과 필수(07 연계). 샘플 PR: #1 (형식 참고)
- 결정일: 2026-08-05

## 2. 이슈 / 작업 관리

### 이슈 관리 도구
- 상태: ✅ 결정
- 선택지: 없음(WBS만) / GitHub Issues / Jira / Notion
- 결정: **팀 노션(PM 워크스페이스)** — 팀 작업 관리가 이미 PM 노션에서 진행 중이라 일원화
- 이유: 중복 방지 (2026-08-05 인터뷰)
- 결정일: 2026-08-05

### 이슈 작성 규칙
- 상태: ✅ 결정
- 결정: 브랜치명 `feat/짧은-설명` 형식(예: `feat/attendance-judge`) — 노션은 이슈 번호가 없으므로 PR 본문에 해당 노션 작업 링크 첨부로 연결
- 결정일: 2026-08-05
