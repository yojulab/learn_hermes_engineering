### 커밋 시점 (일정 업무별 커밋) 🧩
- 상태: 🧩 기본값
- 결정: **업무 묶음이 끝나 검증(07)을 통과하면 그때마다 바로 커밋한다.** 묶음 여러 개를 모아서 한꺼번에 커밋하지 않는다
- 이유: 사용자가 여러 프로젝트에서 반복 지시 — "특정 업무 묶음마다 commit 진행, 하네스 프롬프트에 명기", "일정 업무별 commit"
- 업무 묶음 = 아래 중 하나가 끝난 시점:

  | 묶음 종류 | 커밋 시점 | 접두어 |
  |---|---|---|
  | WBS 작업 1건 (`T-xxx`) | 구현 + 검증 + specs 동기화 완료 | `feat:` |
  | 스펙 단위 기능 (`API-xxx`, `SCR-xxx`, `BAT-xxx`, `LLM-xxx`) | 해당 스펙 하나가 동작·검증됨 | `feat:` |
  | 버그·이슈 1건 | 재현 → 수정 → 재검증 + changelog 기록 | `fix:` |
  | 문서·규칙·하네스 변경 | rules/specs/진입점 파일 갱신 완료 | `docs:` / `chore:` |
  | 리팩터링·의존성·설정 | 동작 변화 없이 검증 통과 | `refactor:` / `chore:` |
  | 큰 작업 중간 지점 | 위험한 변경 직전, 그때까지 통과한 상태 저장 | 해당 접두어 |

- 규칙:
  - 검증에 실패한 상태, 빌드가 깨진 상태로 커밋하지 않는다. (5회 반복으로도 못 고쳤으면 커밋하지 않고 보고한다)
  - 한 커밋에는 한 묶음만 담는다. 관련 없는 변경이 섞였으면 나눠서 커밋한다
  - 사용자가 "커밋하지 마"라고 하지 않는 한 커밋을 생략하지 않는다
  - 작업 보고에 이번에 만든 커밋 목록(해시·메시지)을 적는다
  - git을 직접 실행할 수 없는 AI(L1·L2, AGENT_GUIDE 0-2)는 묶음이 끝날 때마다 `git add <파일…>` / `git commit -m "<메시지>"` 명령을 출력한다
- 결정일:

- 상태: 🧩 기본값
- 결정:
